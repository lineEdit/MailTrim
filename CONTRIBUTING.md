# Contributing

Работайте в отдельной ветке; перед PR выполните Release-сборку, core checks и WebView2 smoke из `docs/TESTING.md`. Не добавляйте реальные браузерные профили и персональные данные в фикстуры. Новое правило должно сопровождаться описанием области действия и проверкой, что оно не скрывает письма/редактор.

Изменения узлов авторизации требуют отдельного рассмотрения: точный HTTPS-host, официальное происхождение и проверка сценария входа. Не добавляйте wildcard-доверие всем поддоменам mail.ru или vk.com. Не отключайте sandbox, TLS, проверку происхождения или подтверждение внешнего перехода ради совместимости.

Для релизов используйте `scripts/Publish.ps1`; проверяйте SHA-256 и содержимое ZIP, затем выполняйте ручной чеклист. Тег создаёт черновик предварительного релиза. До стабильного выпуска нужны проверка авторизованной почты и, желательно, подпись Windows-бинарников.
