# Gmail через официальный API

С версии 0.15.0 можно добавить Gmail рядом с Mail.ru. Gmail работает в собственной панели MailTrim через Gmail API. Вход Google открывается в системном браузере: пароль Google приложение не получает, встроенный браузер для авторизации не используется.

## Подключение своего аккаунта

1. Откройте [Google Cloud Console](https://console.cloud.google.com/), создайте или выберите свой проект.
2. В **APIs & Services → Library** включите **Gmail API**.
3. В **Google Auth Platform** настройте название приложения и контактный адрес. Для личного Gmail выберите аудиторию **External**. При статусе **Testing** добавьте свой Gmail в **Test users**. Названия разделов Google могут меняться.
4. В **Clients** создайте OAuth client с типом **Desktop app**. Скачайте JSON этого клиента. Клиент типа Web application не подходит.
5. В MailTrim нажмите **+ → Gmail (официальный API)**, задайте название вкладки.
6. В панели Gmail откройте **Подключение Gmail → Импортировать JSON → Войти через браузер**. Завершите вход Google и подтвердите доступ. Вернитесь в MailTrim. Вход можно отменить кнопкой в панели; ожидание ограничено тремя минутами.

Параметры клиента нужны только на вашем компьютере. Не добавляйте скачанный JSON, токены или содержимое писем в репозиторий и не отправляйте их в issue. В приложение не встроен общий OAuth client: каждый пользователь подключает свой проект.

MailTrim запрашивает `https://www.googleapis.com/auth/gmail.modify`: чтение, отправка и изменение меток, без окончательного удаления писем. Это restricted scope Google. Для публичного распространения приложения с общим OAuth-проектом может потребоваться проверка Google; наличие открытого репозитория её не заменяет. [Описание разрешений](https://developers.google.com/workspace/gmail/api/auth/scopes).

У проекта External в статусе Testing refresh token для Gmail обычно истекает через **7 дней**. После этого потребуется повторный вход. Это ограничение Google, а не потеря локального пароля. [Правила срока действия токенов](https://developers.google.com/identity/protocols/oauth2#expiration).

## Как работает панель

- Стандартные папки и пользовательские метки доступны слева. Поиск использует синтаксис Gmail, например `is:unread`, `from:адрес` или `after:2026/01/01`.
- Страница содержит до 30 писем; **Ещё** загружает следующую. Сортировка — по точному времени Gmail, новые сверху. Письма показываются отдельно, не объединяются в цепочки.
- Текст и изображения отрисовываются собственными элементами Windows. HTML и JavaScript писем не выполняются; рекламный интерфейс Gmail не загружается. Изображения зависят от общей настройки **Автоматически загружать картинки** и по умолчанию требуют нажатия. Для HTML-писем отображается извлечённый текст; оригинальную вёрстку можно открыть в Gmail.
- Чтение через API и фоновая подготовка не помечают письмо прочитанным. Статус меняется отдельной кнопкой **Прочитано / Не прочитано**.
- Есть ответ и новое текстовое письмо с подтверждением отправки, архивирование, перенос в корзину и сохранение вложений. При неоднозначной сетевой ошибке отправка автоматически не повторяется. Проверьте «Отправленные» перед повтором.
- Черновик нового письма хранится в открытой панели: переключение вкладки его сохраняет, полный выход предупреждает о потере. Серверные черновики показываются для просмотра; продолжить их редактирование и добавить вложения к исходящему письму пока можно в веб-интерфейсе Gmail.
- Непрочитанные во **Входящих** получаются из `messagesUnread` Gmail API. Проверка выполняется при подключении и затем примерно раз в две минуты, в том числе в трее. Первая проверка не уведомляет о старых письмах. Настройка уведомлений управляет уведомлениями Gmail независимо от уведомлений сайта Mail.ru.
- Сохранённые заголовки и подготовленные тела отображаются сразу, затем обновляются из API. Кэш зашифрован Windows для текущего пользователя и разделён по профилям. Он ограничен 100 подготовленными письмами и 40 первыми страницами папок; это **не полная резервная копия Gmail**. Общая настройка автоматического кэширования разрешает подготовку до восьми уже прочитанных писем текущей страницы за проход. Непрочитанные не открываются фоновым подготовщиком.

## Выход и безопасность

**Подключение Gmail → Отключить и очистить локальные данные** или **⋯ → Очистить сессию** удаляет локальные токены и кэш профиля. Серверные письма остаются. Разрешение приложения в Google при необходимости отзывается отдельно в [настройках доступов Google](https://myaccount.google.com/connections).

Локальные данные находятся в `%LOCALAPPDATA%\MailTrim\Gmail\<profile-id>` с ограниченными правами доступа и Windows DPAPI CurrentUser. Их нельзя переносить как рабочую авторизацию на другой компьютер или другому пользователю. Журнал содержит только коды событий. Gmail OAuth использует PKCE, случайный state и временный loopback-порт `127.0.0.1`; браузерный callback не принимает произвольные внешние адреса. [Официальный протокол Desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app).

Автоматические проверки используют искусственные ответы API и изолированные каталоги. Они проверяют MIME, сортировку, безопасную отправку, шифрование и собственную панель. Вход в ваш Google и реальные разрешения проверяются вами после настройки OAuth-проекта.
