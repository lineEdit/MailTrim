# Архитектура

## Два представления одного ящика

В обычном режиме окно показывает официальный сайт в WebView2. `BrowserSession` ограничивает навигацию, применяет сетевые правила и внедряет косметическую очистку. При входе и VK ID сайт остаётся штатным: приложение не запрашивает пароль и не заменяет авторизацию.

В 0.16.1 удалён механизм ожидания и снимков из 0.16.0: обычный режим снова показывает живой WebView2 без опроса готовности, заморозки предыдущего кадра и скрытия всей страницы. `BrowserSurface` — только переносимый контейнер браузера для оригинала и встроенного ответа.

Косметический скрипт ставит CSS при создании документа и синхронно обрабатывает изменения DOM до следующего кадра. Верхние заглушки распознаются как пара пустых крупных прямоугольников с полосами: поиск работает и внутри корня списка. Цвет `rgba` смешивается с фоном родителя, поэтому прозрачный тёмный цвет с малой альфой распознаётся как видимый светло-серый. Известное место удерживается CSS-селектором родителя/позиции при замене содержимого. Письма, редактор, реальные почтовые ссылки и рабочие элементы защищены. Эта эвристика не гарантирует распознавание любой будущей разметки Mail.ru.

В режиме «Только важное» источник WebView2 остаётся работающим, но скрыт. Страница не передаётся напрямую на экран: `ReaderScript` извлекает письма, `ReaderData` ограничивает и очищает данные, а `ReaderPane` создаёт собственное WPF-представление. Текст и ссылки на картинки проходят через модели данных; HTML письма и его JavaScript не исполняются в этом представлении.

```text
Официальный сайт → скрытый WebView2 → парсер страницы
                                      ↓
                               очищенные модели
                                      ↓
                         ReaderDataService → ReaderPane
                                      ↕
                              MessageCache (DPAPI)
```

Внешний брокер сообщений не используется. У каждого профиля своя ограниченная очередь `ReaderDataService`: операции навигации и чтения выполняются последовательно. Отмена и проверка актуальности выбранного письма предотвращают отображение запоздалого результата предыдущего запроса. Браузерные операции выполняются на UI-потоке.

## Источник и кэш

Группы умной сортировки распознаются по устойчивому списку в DOM открытой страницы при отсутствии области тела письма, а не по имени отправителя. `ReaderGroupOpened` передаёт уже извлечённые строки через ту же очередь в нативный список; группа добавляется к папкам. Подтверждённый тип сохраняется в зашифрованных заголовках (`IsGroup`), не допускает кэширования тела и команд над письмом. Внутренние маршруты групп с параметрами разрешаются для обновления только после такого подтверждения; обычная проверка URL папок остаётся строгой. Переход в группу не открывает её дочерние письма. Изменения разметки Mail.ru могут потребовать обновления распознавания.

`ReaderSource` связывает очередь с WebView2. `LoadFolder` получает строки выбранной папки из DOM; первый достоверный ответ заменяет локальный предварительный список. `ReaderPane` проверяет изменения открытого списка раз в две секунды, а раз в минуту при простое снова загружает выбранную папку. Недавно проверенная готовая структура отображается без новой навигации; остальные выбранные письма проверяются через `ReadFresh`. Предварительный текст и резерв при ошибке сайта остаются доступны; результат сайта заменяет их только после проверки отмены и текущего выбора. Одинаковые блоки не перерисовываются.

`PreparedMessageStore` принадлежит `ReaderDataService` одного профиля: это очищенные неизменяемые блоки и время последней успешной проверки, без DOM или исполняемого HTML. LRU ограничивает 80 документов и 4 миллиона символов; свежесть длится пять минут и сбрасывается изменением метаданных или ручным обновлением. `HydratePrepared` читает зашифрованные файлы вне UI-потока порциями по восемь документов; локальная старая копия не заменяет свежую структуру. `ReaderPane` подготавливает до 20 последних подтверждённо прочитанных писем по одному, используя ту же очередь и отмену с приоритетом действий пользователя. Неизвестный статус не выводится из отсутствия unread-класса. Подготовка ограничена восемью секундами на письмо; после ошибки действует минутная задержка. Очистка профиля и кэша удаляет готовые структуры.

Источник один на профиль, поэтому просмотр текста, проверка списка и действия сайта проходят через ту же ограниченную очередь. При чтении текста фон откладывается, при ответе и поиске переходов нет; закрытие отменяет запросы. Полный обход доступных папок запускается отдельно. Сайт виртуализирует строки: сохранение ранее полученных страниц списка не доказывает присутствие каждой строки на сервере; для нового снимка используется ручное обновление.

`MessageCache` хранит отдельные документы и индекс заголовков, использует DPAPI CurrentUser с привязкой к профилю и атомарную запись. Индекс и объём данных ограничены. Кэш не отражает автоматически все серверные удаления и не гарантирует полноту скрытых или виртуализированных папок.

Папки отображаются в собственной сворачиваемой WPF-панели. `FolderDetails` получает ограниченный набор названий и допустимых адресов с официальной страницы, исключая ссылки на действия и внешние сайты. В каждой загрузке папки используется отдельный токен отмены: новый выбор прекращает предыдущую навигацию, её ответ не меняет новый список и не сбрасывает состояние загрузки нового запроса. Ответ и выполняемые действия не допускают смену папки. Видимость панели хранится в настройках независимо от ширины списка писем.

`ReaderChronology` использует извлечённые даты и время захвата относительных дат. Неизвестная дата не превращается в текущую. Поиск работает только с доступными локальными данными выбранного профиля.

## Действия с письмом

`ReaderActionScript` ищет штатные элементы управления открытого письма и проверяет контекст перед действием. Ответ открывается в официальном редакторе рядом с собственным списком. Отправка требует явного действия пользователя. Приложение не считает операцию успешной только потому, что удалось нажать кнопку; переходы и ошибки могут потребовать возврата в оригинал.

## Очистка и навигация

`Filtering/Policy.cs` содержит формат правил, политику навигации и построение косметического скрипта. Сетевые фильтры проверяют домены по границе имени, с приоритетом исключений и защитой официальной почты и входа. Узкие рекламные пространства `/api-proxy/` блокируются отдельным правилом.

CSS и поиск коротких рекламных меток действуют только в главном документе `e.mail.ru`. Известные контейнеры писем и редактора защищены. Оригинал остаётся живым WebView2 без снимков и ожидания кадра. В режиме чтения сам интерфейс сайта скрыт, поэтому его реклама не становится частью собственной отрисовки.

## Профили и Windows

`LocalStore` хранит настройки, мигрирует стандартные правила и пишет журнал с кодами событий без содержимого писем. У профилей отдельные GUID и каталоги браузера. `MailMonitor` использует служебные WebView2 с теми же сессиями для последовательной проверки почты. `NewMailTracker` различает исходное состояние, изменение и отсутствие достоверного счётчика.

`DesktopIntegration` отвечает за трей, автозапуск и уведомления, `WindowPositionManager` — за размещение окна. Политика браузерных уведомлений ограничивает разрешённый источник и подавляет повторные доставки из служебных окон.

## Обновления

`UpdateChecker` получает релизы GitHub. Core проверяет каталог, допустимые адреса загрузки, SHA-256 и содержимое ZIP. `UpdateInstaller` устанавливает новую версию в отдельную папку и передаёт ей запуск. Подтверждение готовности ограничено по времени; при неудаче запускается предыдущая версия. Проверка наличия релиза не равна согласию на установку.

Границы приватности и ограничения браузерного хранилища описаны в [SECURITY.md](../SECURITY.md). Автоматические проверки компонентов — в [TESTING.md](TESTING.md).

## Облако Mail: модели и свой интерфейс

BrowserSession.EnsureCloud лениво создаёт WebView2 с тем же environment и профилем, что у почты. CloudOpen выбирает рабочую область, а CloudOriginal отдельно разрешает видимость сайта. По умолчанию CloudSurface скрыт, CloudHost содержит CloudPane — WPF-контролы из проверенных CloudItem/CloudFolder/CloudListing. Содержимое сайта, его HTML и рекламные изображения в эту панель не передаются.

CloudDataService сериализует навигацию и чтение в отдельной очереди SemaphoreSlim на профиль. CloudScript читает только подтверждённые контейнеры файлов и строки с типом/именем/путём. Поддержаны семантические фикстуры и настоящие data-qa-атрибуты DataList/строк, подтверждённые публичным официальным react-bundle. В URL Cloud кодируется целый путь объекта; ParentUrl/FolderPath учитывают это. Формы, промо, модальные диалоги и предпросмотр исключены. Обычные таблицы оформления не считаются списками файлов.

Пустой Home подтверждается официальной веткой Welcome-компонента при загруженном корне без дочерних объектов; один текст «Добро пожаловать» не считается доказательством. Unknown, AuthRequired, Empty и Partial остаются отдельными состояниями. C# дополнительно ограничивает поля, число объектов и exact-origin URL. Неподтверждённая структура не вызывает перехода в оригинал.

Для виртуализированного списка LoadMore выполняет только явную прокрутку подтверждённого контейнера и читает новые строки. Модели объединяются по проверенному URL с лимитом 2000; список остаётся Partial, пока нет подтверждения полноты. Пассивное обновление читает текущую страницу без навигации и сохраняет уже загруженные части/позицию. Ручное обновление перезагружает папку. Облачные модели пока не записываются в почтовый кэш.

Скрытые главные источники не открывают popup, script-dialog, permission UI или загрузку файла. Перенаправление скрытой страницы в другой сервис не переключает рабочую область. Вход разрешается только явной командой и отдельным официальным окном; после возврата в Cloud/Mail оно закрывается до показа содержимого облака. Original — отдельная явная команда, а не fallback парсера. При очистке CloudPane.StopAsync дожидается очереди перед закрытием обоих документов и очисткой профиля.

Theme.xaml содержит общие стили NativeTitle/Metadata/Body/List/ListItem/SearchBox/ToolbarButton. Они применяются в собственной почте и облаке и используют динамические цвета. CSS провайдера остаётся в скрытом WebView2/оригинале; копирования произвольных стилей или JS в WPF нет.

## Фильтрация явно открытого оригинала облака

CloudCosmeticScript сохраняется для оригинала. Он распознаёт предложения места/подписки, приглашения в каналы, установку приложений и рекламные акции; изолированная оболочка и затемнение скрываются до кадра. Кнопка закрытия может нажиматься однократно; рекламные CTA не активируются. Этот фильтр не является границей собственного интерфейса: граница проходит по проверенным моделям, и неизвестный промо-блок не имеет представления в CloudPane.
