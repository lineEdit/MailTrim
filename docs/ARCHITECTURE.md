# Архитектура

## Два представления одного ящика

В обычном режиме окно показывает официальный сайт в WebView2. `BrowserSession` ограничивает навигацию, применяет сетевые правила и внедряет косметическую очистку. При входе и VK ID сайт остаётся штатным: приложение не запрашивает пароль и не заменяет авторизацию.

В режиме «Только важное» источник WebView2 остаётся работающим, но скрыт. Страница не передаётся напрямую на экран: `ReaderScript` извлекает письма, `ReaderData` ограничивает и очищает данные, а `ReaderPane` создаёт собственное WPF-представление. Текст и ссылки на картинки проходят через модели данных; HTML письма и его JavaScript не исполняются в этом представлении.

```text
Официальный сайт → скрытый WebView2 → парсер страницы
                                      ↓
                               очищенные модели
                                      ↓
                         ReaderDataService → ReaderPane
                                      ↕
                              MessageCache (DPAPI)
```

Внешний брокер сообщений не используется. У каждого профиля своя ограниченная очередь `ReaderDataService`: операции навигации и чтения выполняются последовательно. Отмена и проверка актуальности выбранного письма предотвращают отображение запоздалого результата предыдущего запроса. Браузерные операции выполняются на UI-потоке.

## Источник и кэш

`ReaderSource` связывает очередь с WebView2. `LoadFolder` получает строки выбранной папки из DOM; первый достоверный ответ заменяет локальный предварительный список. `ReaderPane` проверяет изменения открытого списка раз в две секунды, а раз в минуту при простое снова загружает выбранную папку. Выбранное письмо проверяется через `ReadFresh`, даже если уже сохранено. Кэш даёт немедленный предварительный просмотр и резерв при ошибке сайта; результат сайта заменяет его только после проверки отмены и текущего выбора. Одинаковые блоки не перерисовываются.

Источник один на профиль, поэтому просмотр текста, проверка списка и действия сайта проходят через ту же ограниченную очередь. При чтении текста фон откладывается, при ответе и поиске переходов нет; закрытие отменяет запросы. Полный обход доступных папок запускается отдельно. Сайт виртуализирует строки: сохранение ранее полученных страниц списка не доказывает присутствие каждой строки на сервере; для нового снимка используется ручное обновление.

`MessageCache` хранит отдельные документы и индекс заголовков, использует DPAPI CurrentUser с привязкой к профилю и атомарную запись. Индекс и объём данных ограничены. Кэш не отражает автоматически все серверные удаления и не гарантирует полноту скрытых или виртуализированных папок.

Папки отображаются в собственной сворачиваемой WPF-панели. `FolderDetails` получает ограниченный набор названий и допустимых адресов с официальной страницы, исключая ссылки на действия и внешние сайты. В каждой загрузке папки используется отдельный токен отмены: новый выбор прекращает предыдущую навигацию, её ответ не меняет новый список и не сбрасывает состояние загрузки нового запроса. Ответ и выполняемые действия не допускают смену папки. Видимость панели хранится в настройках независимо от ширины списка писем.

`ReaderChronology` использует извлечённые даты и время захвата относительных дат. Неизвестная дата не превращается в текущую. Поиск работает только с доступными локальными данными выбранного профиля.

## Действия с письмом

`ReaderActionScript` ищет штатные элементы управления открытого письма и проверяет контекст перед действием. Ответ открывается в официальном редакторе рядом с собственным списком. Отправка требует явного действия пользователя. Приложение не считает операцию успешной только потому, что удалось нажать кнопку; переходы и ошибки могут потребовать возврата в оригинал.

## Очистка и навигация

`Filtering/Policy.cs` содержит формат правил, политику навигации и построение косметического скрипта. Сетевые фильтры проверяют домены по границе имени, с приоритетом исключений и защитой официальной почты и входа. Узкие рекламные пространства `/api-proxy/` блокируются отдельным правилом.

CSS и поиск коротких рекламных меток действуют только в главном документе `e.mail.ru`. Известные контейнеры писем и редактора защищены. Начальная маска ограничивает промаргивание рекламы; её таймаут возвращает видимость страницы, если очистка не завершилась. В режиме чтения сам интерфейс сайта скрыт, поэтому его реклама не становится частью собственной отрисовки.

## Профили и Windows

`LocalStore` хранит настройки, мигрирует стандартные правила и пишет журнал с кодами событий без содержимого писем. У профилей отдельные GUID и каталоги браузера. `MailMonitor` использует служебные WebView2 с теми же сессиями для последовательной проверки почты. `NewMailTracker` различает исходное состояние, изменение и отсутствие достоверного счётчика.

`DesktopIntegration` отвечает за трей, автозапуск и уведомления, `WindowPositionManager` — за размещение окна. Политика браузерных уведомлений ограничивает разрешённый источник и подавляет повторные доставки из служебных окон.

## Обновления

`UpdateChecker` получает релизы GitHub. Core проверяет каталог, допустимые адреса загрузки, SHA-256 и содержимое ZIP. `UpdateInstaller` устанавливает новую версию в отдельную папку и передаёт ей запуск. Подтверждение готовности ограничено по времени; при неудаче запускается предыдущая версия. Проверка наличия релиза не равна согласию на установку.

Границы приватности и ограничения браузерного хранилища описаны в [SECURITY.md](../SECURITY.md). Автоматические проверки компонентов — в [TESTING.md](TESTING.md).
