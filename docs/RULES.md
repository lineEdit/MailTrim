# Правила фильтрации

## Формат v1

```json
{
  "schemaVersion": 1,
  "revision": "local-example.1",
  "blockedMailPathPrefixes": ["/api-proxy/rb-mimic/"],
  "removeLabeledAds": true,
  "blockedDomains": ["ads.example.org"],
  "allowedDomains": ["useful.ads.example.org"],
  "hideSelectors": ["[data-testid=\"advertisement\"]"],
  "aggressiveSelectors": ["[data-testid=\"promo\"]"]
}
```

Это пример формата. Полный набор — в [rules/default.json](../rules/default.json).

Домены в нижнем регистре, без URL, путей, `*` и ведущей точки. Совпадение учитывает домен и его поддомены по границе точки; исключения имеют приоритет. Точные HTTPS-узлы входа и почты защищены от сетевой блокировки.

`blockedMailPathPrefixes` принимает узкие пространства `/api-proxy/имя/` на `https://e.mail.ru`, с границей завершающего слеша. Это отдельное исключение для рекламного прокси: обычные API сообщений и авторизация защищены. Исключение `e.mail.ru` в `allowedDomains` отключает и эту блокировку.

Ограничения: 256 КБ на файл, 500 записей в списке, 500 символов на селектор. Неверные селекторы пропускаются браузером. JSON не позволяет загружать удалённый JavaScript.

## Косметическая очистка

`hideSelectors` действует при включённых CSS-фильтрах, `aggressiveSelectors` — ещё и при включённой дополнительной очистке. CSS не внедряется во фреймы писем и страницы входа. Избегайте общих селекторов `body`, `main`, `iframe`, `[class*=ad]`: они могут скрыть почту.

`removeLabeledAds` включает поиск коротких самостоятельных подписей «Реклама», «Advertisement» и «Sponsored». Обрабатываются карточки и строки, включая вложенные метки и позднюю вставку. Контейнеры тела письма, редактор и обычные почтовые ссылки исключаются. Если виртуализированная рекламная строка превращается в письмо, видимость восстанавливается.

Начальная маска ограничивает промаргивание рекламы, а её таймаут возвращает видимость при неудаче очистки. Эвристики требуют проверки при изменении разметки сайта.

После изменения проверяйте входящие, письмо, редактор, поиск и вложения. Добавляйте обезличенный пример в тестовые фикстуры `tests/MailTrim.Smoke/Fixtures/`.

## Импорт и совместимость

При сохранении сначала разбирается набор, затем атомарно заменяется локальный файл. Ошибочный импорт не заменяет активные правила. При повреждении файла используются встроенные правила с предупреждением; исходный файл сохраняется.

Неизменённый старый стандартный набор мигрирует автоматически с резервной копией. Пользовательский набор не перезаписывается: новый можно выбрать кнопкой «Встроенные правила» после сохранения своих правок. `rules/legacy-*.json` нужны для распознавания старых наборов.

JSON можно приложить к релизу и импортировать без нового EXE. Изменение самого алгоритма требует выпуска приложения. Источники селекторов и лицензии — в [THIRD-PARTY-NOTICES.md](../THIRD-PARTY-NOTICES.md).
