# Правила v1

```json
{
  "schemaVersion": 1,
  "revision": "2026-09-30.1",
  "blockedMailPathPrefixes": ["/api-proxy/rb-mimic/"],
  "removeLabeledAds": true,
  "blockedDomains": ["ads.example.org"],
  "allowedDomains": ["useful.ads.example.org"],
  "hideSelectors": ["[data-testid=\"advertisement\"]"],
  "aggressiveSelectors": ["[data-testid=\"promo\"]"]
}
```

Домены в нижнем регистре, без URL, путей, `*` и ведущей точки. Правило совпадает с доменом и его поддоменами по границе точки. Исключения имеют приоритет. Точные HTTPS-узлы входа и почты защищены от сетевой блокировки. Ограничения: 256 КБ, 500 записей в списке, 500 символов на селектор. Селекторы проверяются браузером; синтаксически неверные пропускаются.

Обычные селекторы действуют при включённых CSS-фильтрах, дополнительные — ещё и при включённой соответствующей настройке. CSS не внедряется во фреймы писем и страницы входа. Избегайте общих селекторов `body`, `main`, `iframe`, `[class*=ad]`: они могут скрыть почту. Проверяйте входящие, письмо, редактор, поиск и вложения после каждого изменения.

При сохранении сначала разбирается новый набор, затем атомарно заменяется локальный файл. Ошибочный импорт не заменяет активные правила. При повреждении файла между запусками включаются встроенные правила и показывается предупреждение; исходный файл остаётся для исправления.

Обновление для пользователей: прикладывайте JSON к GitHub-релизу. Пользователь скачивает его, импортирует в настройках и подтверждает перезагрузку. Это работает независимо от выпуска нового EXE.

В 0.1.1 добавлены `blockedMailPathPrefixes` (только точные пространства `/api-proxy/имя/` на `https://e.mail.ru`, с границей завершающего слеша) и `removeLabeledAds`. Обычные API сообщений и узлы авторизации остаются защищены; исключение для `e.mail.ru` в `allowedDomains` отключает и блокировку рекламного прокси. Старое приложение 0.1.0 не поддерживает эти новые поля: для нового поведения JS и сетевых правил нужно обновить EXE.

Очистка по меткам проверяет короткие самостоятельные подписи «Реклама», «Advertisement», «Sponsored» в карточках и строках. Она исключает известные контейнеры тела письма, редактор и карточки с обычной внутренней ссылкой почты. Строки проверяются заново при изменении DOM; если рекламная строка превращается в настоящее письмо, её видимость восстанавливается. Эвристика не заменяет проверку текущего интерфейса Mail.ru.

При обновлении с 0.1.0 неизменённые стандартные правила заменяются автоматически; прежний файл сохраняется как `rules.json.backup`. Изменённый набор не перезаписывается: новый можно выбрать кнопкой «Встроенные правила» после сохранения собственных правок. Источники части селекторов и лицензия — в `THIRD-PARTY-NOTICES.md`.
