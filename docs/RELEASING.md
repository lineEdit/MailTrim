# Выпуск версии

## Источники версии и заметок

Версия продукта задаётся только в `Directory.Build.props`. Перед выпуском перенесите готовые изменения из `## Unreleased` в раздел `## <версия>` в `CHANGELOG.md`. `Publish.ps1` извлекает только этот раздел в `artifacts/release-notes.md`; весь журнал изменений не становится описанием одного релиза.

Тег должен точно совпадать с версией: например, для версии `0.12.6` — `v0.12.6`. Pipeline проверяет совпадение перед сборкой. Изменения документации и структуры без изменения поведения можно оставить в `Unreleased`, без нового тега.

## Перед тегом

1. Выполните `./scripts/Check.ps1` и подходящие ручные проверки из [TESTING.md](TESTING.md).
2. Выполните `./scripts/Publish.ps1`, проверьте состав архива и его SHA-256.
3. Проверьте настоящий пакет тестом установки, подставив текущую версию и новую тестовую папку:

```powershell
dotnet run --project tests/MailTrim.UpdateTests -c Release --no-build -- --verify-package artifacts/MailTrim-0.12.8-win-x64.zip C:\Temp\mailtrim-package-check-unique
```

4. Зафиксируйте изменения и отправьте их в репозиторий. Убедитесь, что Windows pipeline зелёный, затем создайте и отправьте тег версии.

Не перезаписывайте уже опубликованный тег, ZIP или контрольную сумму. Исправленный пакет получает новую версию.

## Что делает GitHub Actions

[Windows pipeline](https://github.com/lineEdit/MailTrim/blob/main/.github/workflows/windows.yml) запускается на push, pull request и вручную. Он восстанавливает зависимости в locked mode, собирает Release, запускает три набора через `Check.ps1`, упаковывает Windows x64 и проверяет настоящий ZIP тестом установки.

Проверка пакета также запускает включённый в архив EXE с отдельным профилем и локальной HTML-страницей. Она подтверждает работу WPF-ресурсов и загрузчика WebView2 в сборке single-file, сохраняя изоляцию от личных ящиков.

Артефакт сборки содержит ZIP, SHA-256 и заметки текущей версии; срок хранения — 30 дней. Ссылка отображается в сводке запуска. Сборки веток не создают GitHub Release и не доступны механизму обновлений как релизы.

Тег `v*` дополнительно создаёт **черновик предварительного релиза** с ZIP, SHA-256 и `rules/default.json`. Черновик не виден обычным пользователям и не предлагается приложением. После проверки откройте черновик в GitHub и опубликуйте его; предварительный статус сохраняйте, пока не пройден ручной сценарий с реальной авторизацией.

## Что видит приложение

Проверка обновлений обращается к опубликованным релизам настроенного GitHub-репозитория. По умолчанию разрешены предварительные версии; при отключении этой настройки они исключаются. Для установки нужен Windows x64 ZIP с SHA-256 и версией новее текущей.

Проверка не устанавливает обновление. Загрузка и запуск происходят после действия пользователя. Новая копия устанавливается отдельно от текущей, данные профилей сохраняются. Подробности и возврат после неудачного запуска — в [руководстве пользователя](USER-GUIDE.md).

Дистрибутив пока не имеет Authenticode-подписи. SHA-256 проверяет целостность пакета, но сам по себе не удостоверяет издателя. Лицензии и WebView2-уведомления должны оставаться в архиве.
