# Безопасность и приватность

MailTrim использует только официальный веб-интерфейс. Нет собственного поля пароля, перехвата паролей, IMAP/SMTP, обхода 2FA или экспорта cookies.

## Границы доверия

- Каждый профиль имеет случайный GUID и отдельную папку WebView2 в `%LOCALAPPDATA%\MailTrim\Profiles`.
- Корневая папка получает Windows ACL для текущего пользователя, SYSTEM и администраторов. Cookies и другие данные управляются WebView2; приложение не реализует собственную криптографию. **Не всё содержимое браузерного профиля зашифровано**: кэш и данные сайтов могут содержать письма. Изоляция не защищает от вредоносного ПО под тем же Windows-пользователем или администратора.
- Парольный менеджер и автозаполнение WebView2 отключены. Host objects, web messages и DevTools отключены. Sandbox и проверка сертификатов не отключаются.
- Верхний документ ограничен HTTPS и точным списком узлов в `NavigationPolicy`. Внешние переходы по инициативе пользователя требуют подтверждения; фоновые внешние редиректы останавливаются. Произвольные протоколы, локальные файлы и URL с userinfo не запускаются оболочкой.
- Подресурсы/фреймы остаются под контролем браузерной same-origin policy, с фильтром рекламных доменов. Список верхних страниц не является сетевым firewall для всех подресурсов.
- Встроенный косметический JS работает только на `https://e.mail.ru` в главном фрейме. Он вставляет CSS и обрабатывает короткие метки рекламы, исключая известные контейнеры тела письма/редактора и внутренние почтовые ссылки. Метки и содержимое DOM не отправляются наружу и не журналируются. JSON принимает селекторы, а не JS/CSS-декларации. Импорт правил может скрыть нужные элементы: изучайте правила перед применением.
- Cookies, заголовки, тела запросов, письма, названия профилей, адреса и полные URL не записываются в журнал приложения. WebView2 хранит собственные браузерные данные отдельно.
- Очистка удаляет браузерные данные через `ClearBrowsingDataAsync(AllProfile)` после ухода со страницы. Пустая служебная папка профиля может остаться. Это не гарантированное стирание диска, не отзыв серверных токенов и не удаление писем.
- Проверка релизов обращается к GitHub, когда пользователь её запускает или включает. EXE не скачиваются и не исполняются автоматически. Список правил обновляется вручную, не из недоверенного удалённого скрипта.

Не запускайте приложение от администратора и не отправляйте папку Profiles при сообщении об ошибке. Для отчёта достаточно версии, Windows/WebView2, описания и обезличенного `events.log`. Не включайте скриншоты писем или персональные URL в публичные issues.

Основание решений: [Microsoft WebView2 security](https://learn.microsoft.com/microsoft-edge/webview2/concepts/security), [user data folders](https://learn.microsoft.com/microsoft-edge/webview2/concepts/user-data-folder).

Для уязвимостей используйте private vulnerability reporting репозитория, если оно включено. Не публикуйте токены, данные сессии или персональные письма.
- С версии 0.3.0 отдельный кэш чтения сохраняет текст, заголовки и ссылки на изображения через Windows DPAPI CurrentUser. GUID профиля используется как дополнительная привязка. Имена файлов — SHA-256 URL. Запись атомарная через зашифрованный временный файл; очистка сессии удаляет этот кэш. Он не синхронизирует удаление писем на сервере и не защищает от программ того же пользователя Windows.

- С версии 0.6.0 отдельная настройка разрешает штатные браузерные уведомления только от HTTPS e.mail.ru. Они могут содержать отправителя и тему и отображаются средствами WebView2/Windows; приложение их не журналирует. Разрешение не сохраняется в профиле, отключение уведомлений проверяется также в обработчике доставки. Служебные окна опроса всегда подавляют уведомления.
